策划与文案设计

本技能采用标准化“s0–s6”脚本结构：s0 引子吸引注意，s1–s2 书名报幕与作者背景，s3–s5 核心论点铺陈，s6 寄语收束。

s0 引子 抛出悬念与时代痛点，第一时间吸引注意。
s1–s2 报幕与背景 书名报幕，交代作者生平与写作语境。
s3–s5 核心论证 分层铺陈全书核心论点与关键概念。
s6 寄语收束 回扣现实，以寄语收尾完成情绪落点。
画面描述采用“现代新闻纪录片风格”，结合高对比度、霓虹灯、冷色调等视觉元素，使抽象论点获得统一且可辨识的视觉表达。

作品展示与流程验证

本技能采用“先跑通流程，再复用测试”的开发方法。首先以《娱乐至死》为例跑通全流程，随后将该技能直接复用于《乌合之众》，验证技能的通用性与稳定性。

STAGE 01 · 跑通流程
第一阶段 流程开发与跑通 —— 以《娱乐至死》为例，跑通全流程

通过本书测试了从剧本生成、ARK 生图、豆包 TTS 2.0 配音到视频合成的完整链路，解决了各种 API 兼容和画面倒放问题。

技术路线：本阶段为踩坑与修正期，逐一攻克密钥权限、TTS 版本兼容、转场效果三类问题，把全链路首次打通。

STAGE 02 · 复用验证
第二阶段 技能复用与验证 —— 输入《乌合之众》，验证技能复用能力

在技能封装完成后，直接输入新书名，系统自动生成全套素材并合成视频，验证了技能无需人工干预即可复用。

技术路线：本阶段为无缝复用期，沿用第一阶段固化的技能流程，仅替换书名输入即可产出成片，无需再次调试。

踩坑与开发感悟

01
API 兼容

解决了不同 API 需要独立密钥的权限问题。图片生成与语音合成分属不同控制台、不同凭据体系，必须分别申请与配置，不能混用。

02
TTS 双向流

解决了豆包 TTS 1.0 与 2.0 版本兼容问题。账户实际开通的是 2.0 资源，音色与资源 ID 必须严格匹配，最终使用 WebSocket 双向流协议跑通音频生成。

03
画面倒放修复

修复了“乒乓倒放”（正放–倒放）造成的画面诡异问题，改用 Ken Burns 缓慢推近效果，使静态画面获得平稳、自然的运动感。
